# Renewal quote sources and background recovery

Dynadot keeps working exact classic price-only quotes. If that API rejects a key, the adapter remembers the rejection for one hour and uses the single-domain REST search. That endpoint can return per-name renewal prices for unavailable names; `bulk_search` omits them. Only an explicitly supported annual term is accepted; a two-year .ai renewal is annualized. Responses for a different domain and malformed prices are rejected. REST-unsupported extensions are remembered for one hour so an incompatible key or extension is not probed once for every holding.

Changing lookup strategy requeues the previous strategy's failed names once. Their failure records, saved quotes, retry state and actual cooldown remain until successful reads replace them. Pending retries are not counted twice as final failures. Repeated HTTP 429s retain the current domain and the rest of the queue; after three fast rejections, recovery pauses for at least 30 minutes (or the longer provider Retry-After). Shared/local cooldowns do not consume the short-retry count. The existing 15 pricing steps and 20 provider refresh requests per ten minutes, shared Dynadot lane, credentials and selected routes are unchanged.

A verified registrar-portal observation can be retained in the encrypted, account-scoped `registrar-portal-quotes` cache. The record has `renewal`, `currency` and `observedAt`; the importer must first verify the exact held name, authenticated account, annual term and displayed currency. These records are local, excluded from exports, and cleared with caches. They do not create or replace manual prices. Manual overrides and API quotes retain priority.

Portal observations resolve with source `portal` and the original `observedAt` timestamp. The UI identifies a registrar portal snapshot, MCP retains the source and date, and the admin observer ages it from that date. This supplies a truthful last-known estimate when a registrar's API cannot yet quote the held domain; it does not qualify as an automatic API refresh. Keep captured evidence and import receipts private, and never relabel a portal observation as `api`.

An old engine ignores the separate portal namespace during rollback, and no permanent user override needs to be removed. Verify the rolled-out engine and source, actual provider continuation and the consumer's price provenance separately.
