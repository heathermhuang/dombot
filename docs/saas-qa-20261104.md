## Findings

### P1 Initial portfolio import failed in production

The managed runner created one ordinary-role leased QA identity, signed in, opened the onboarding and import pages, built a valid one-row preview, rejected an empty import and submitted a valid reserved `.invalid` domain. The valid import returned HTTP 503 instead of 200. The runner never reached successful import/readback or idempotent-retry assertions. Do not treat this as a passing production import test or infer that every account is affected from one controlled failure.

The setup route catches activation failures and returns a generic 503. The underlying provisioner error remains unconfirmed. A bounded attempt to read existing historical provisioner logs for the incident window returned HTTP 403. No new import/allocation was submitted to mask or blindly retry the failure.

Cleanup initially recorded `provider_or_inspection_unavailable`, then completed on its second guarded cleanup attempt. Independent checks confirmed zero QA Workers, zero QA databases, no QA user/session or admitted registry entry, and zero setup keys. The temporary password was scrubbed. Preservation passed for all 55 pre-existing users, 39 platform mappings and 532 workspace identities present at this run's baseline. These counts describe this test's comparison, not a historical fleet reconciliation.

Protected receipts are under `.wrangler/saas-qa-20261104/receipts/67c57fa3-0ec9-4044-ae9e-48a0c221fae0/`. Public report material must exclude credential files, user snapshots and provider payloads.

### P2 Password-change success feedback was lost Fixed locally

After a successful password change, `/account/password` cleared the cookie, revoked sessions and redirected to `/login?notice=password-updated`. The email-first login handler ignores that notice; the confirmation exists only on `/login/password`. A user therefore saw no success confirmation or explanation for being signed out.

The redirect now targets `/login/password?notice=password-updated`. A regression exercises the password change, session revocation, cleared cookie and actual destination HTML. It failed on the baseline and passes after the correction, including confirmation text, new-password guidance and absence of a prefilled password. The fix has not been deployed.

### P3 Injected analytics conflicts with the page CSP

Native Chrome DevTools showed the injected `static.cloudflareinsights.com` beacon blocked by `script-src 'self'` on the password sign-in page. Page functionality tested so far still works. Keep the restrictive CSP; reconcile the existing edge analytics injection setting separately. Browser-extension errors were identified by their `chrome-extension://` sources and excluded from application findings.
