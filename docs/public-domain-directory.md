# Canonical public domain directory

Control migration 0022 replaces per-request fleet discovery with `public_domain_routes`. A row locates one tenant/listing/revision and has a monotonic generation; it does not authorize content. Canonical and legacy requests check the selected tenant's current published-only eligibility, then serve through signed public admission. Disabled/closed accounts, lost/recovering control, withdrawn content, and expired control cannot serve. No other tenant is contacted. Conflicting claims are held with a durable manifest. A private draft never creates a route.

Every standalone, bulk and combined writer passes through `SalesStore.preparePublication`, which reserves the exact reviewed publication revision before building the atomic tenant commit. Managed writers fail closed without `DOMBOT_PUBLIC_DIRECTORY`. A failed or unknown reservation/commit leaves a reservation; retry the same review to reconcile the exact revision. An old consumed review cannot relocate a newer publication. Control and tenant commits are separate, with no cross-database atomicity claim. Public reads settle matching reservations; revision mismatch remains unavailable, without guessing a destination. Withdrawal makes tenant content immediately unavailable even while a locator remains. Generation-fenced tombstones prevent a stale withdrawal from removing a new route.

Ownership transfer uses `POST /w/<workspace>/sales/routes/transfer/reviews` with canonical domain, listing UUID and proposed publication revision. Fresh verified DNS control is required. Review shows the generation/state; commit the returned review ID at `/sales/routes/transfer/commit`. Commit checks the same fresh proof and generation. Transfer only reserves the route; publish current terms under a new explicit publication review. No former-owner claim is automatically recycled. Conflict manifests remain available for audit.

Release sequence (not executed): deploy additive control migration 0022; deploy compatible engine/readers and the directory service binding to every admitted tenant, including future on-demand templates; backfill published-only eligible pages in bounded batches; resolve conflict manifests; then switch gateway canonical routing. Do not release #138's capped fleet resolver as the final architecture. Existing main does not yet have canonical URLs.

An operator with fresh admin authentication can POST `/admin/public-domain-backfill/<workspace>` to process at most 100 published names. `public_domain_route_backfill` records the last completed page; errors leave the checkpoint unchanged. Repeat only until that account's `completed_at` is set, then continue to the next admitted account. The migration never reads private inventory/drafts or publishes content. Its compare-and-set mode preserves newer reviewed reservations and existing tombstones when a page was read before a concurrent publication or withdrawal. Hold directory-only activation until every admitted account has a completed checkpoint and the conflict manifest is reviewed. The helper also supports a smaller page limit for deterministic tests. Do not run the backfill or migrations in production under PR-only authorization.

Source contracts: private draft selection records a specific core market account/listing and public-commercial fingerprint. Successful complete listing observation time is separate from provider `updatedAt`, account tests, partial reads and failed account observations. Application freshness policies are explicit per adapter (Afternic/Sedo six hours; Atom one hour), shortened by a known discount expiry. These are bounded claim leases, not provider availability guarantees. Only canonical public identity destinations are generated; they do not create or verify checkout. No numeric financing quote is inferred from availability or payment count. Manual Spaceship/Efty links remain available subject to safe-destination validation.
