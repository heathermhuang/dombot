# Sales operations

Sales is disabled by default. Source, gateway, tenant engine, tenant schema, control schema, public edge, sender and hostname provider are separate releases. Never deploy a repository template over a live gateway configuration: derive the candidate from current settings and preserve all ten workspace bindings, auth settings, legal/source routes and existing secrets.

## Candidate and migration sequence

1. Record exact Git commit, `hosted/dombot-engine.lock.json` version/source/archive hashes, deployed Worker version IDs, current flag/settings fingerprints and schema versions per tenant. Export an encrypted owner backup and retain a recovery copy under existing custody rules. Capture aggregate inventory/event/legacy-publication counts and selected hashes without exposing contents.
2. Apply additive tenant migrations `0004_sales.sql` and `0005_sales_inquiries.sql`; control migrations `0006_sales_delivery.sql` and `0007_sales_hostnames.sql`. Deploy the compatible pinned tenant engine with all Sales writer/intake/mail/host flags off. Do not skip a tenant or infer adoption from a gateway deployment. Validate disabled routes, login/passkeys, portfolio/renewals and old public pages.
3. Enable `DOMBOT_SALES_V1` only on the controlled tenant. Configure `DOMBOT_SALES_ORIGIN` to the canonical `https://domains.domains/w/<immutable-workspace-id>` and preserve the correct public base path. Owner and public request proofs are distinct and bind method/path/query/body. Never expose the owner gateway key on the edge.
4. Review and publish buyer privacy copy before setting `SALES_PRIVACY_REVIEWED=true`. Configure a dedicated Sales Turnstile key/secret with the exact allowed canonical and custom hostnames. Enable intake only after mail readiness and policy gates pass. Do not use the local test key on a deployed external flow.
5. Bind gateway `SALES_EMAIL` to restricted sender `sales@mail.domains.domains`, independent of account/auth delivery. Set explicit low approved daily/monthly limits, verify the account recipient through email (a passkey alone does not enroll it), then qualify actual delivery before setting `SALES_MAIL_DELIVERY_VERIFIED`. Tenant and gateway `SALES_MAIL_ENABLED` must agree. Provider acceptance is not delivery; preserve delivery receipts and a controlled inbox receipt separately. Gateway cron drains bounded due work every two minutes; the existing tenant scheduled cleanup remains separate.
6. Qualify custom-hostname entitlement, allowed apex behavior, fallback origin and costs. Deploy `hosted/wrangler.lander.jsonc` only with actual control DB/workspace bindings, public-only `SALES_EDGE_KEYS`, workers.dev/previews disabled and `SALES_CUSTOM_HOSTS_ENABLED` initially false. Match each tenant's separate `DOMBOT_SALES_EDGE_SECRET`. Add only the named controlled domain to `SALES_HOST_ALLOWLIST`; configure zone, provider token and CNAME target with least privilege. Never commit secrets.
7. Use the authenticated setup flow to snapshot existing apex/www A/AAAA/CNAME/MX/TXT/CAA/NS/DS records, issue TXT proof and reconcile provider state. Preserve mail records. Any DNS replacement needs the named-domain authorization; provider API access alone does not grant it. Activation requires hostname/TLS readiness and a request proving the exact current publication revision. Failed or uncertain provider creation must reconcile existing state before retrying.
8. Run the full controlled custom-domain journey: visit apex/www, submit, scanner GET, explicit confirm, seller inbox/reply, actual buyer mailbox receipt, conversation and reviewed provider handoff. Verify one ambiguous/failed-delivery recovery, pause/unpublish and private restore, plus unchanged existing account/portfolio/publication paths. Record exact versions and fixtures. Only then consider an opt-in cohort.

## Recovery and data handling

Pause or unpublish the listing to remove its public projection immediately. Disable intake/mail/host flags independently for an incident; preserve the outbox and provider receipts. Detach hostnames through the controller before deleting provider state; the controller advances the epoch and the edge rechecks it on every request. Keep hostname registry tombstones through tenant purge so reassignment cannot revive a stale claim. Account suspension/closure denies public routing and sending even if a host record remains active.

A leased batch is not permission to send. The dispatcher records a durable attempt then claims each send once against current tenant lease, expiry, lead eligibility and suppression. Spam invalidates unclaimed leased items. Deletion and restore remove the grant. Once claimed, a provider call can already be in progress; do not promise recall. Unknown provider outcomes and expired leases require explicit reconciliation. Never automatically replay an unknown attempt. Seller fresh-link recovery creates a new bounded attempt and warns about possible duplicate delivery.

For root-key rotation, use the existing export/rotate/import procedure with the Sales-aware host runtime. Validate the entire version-9 extension before mutation. Restore re-encrypts private content and rebuilds keyed metadata, including encrypted suppression addresses; no capabilities or delivery grants are portable. Verify restored drafts/conversations, private notes and suppression, then perform fresh registrar control and buyer confirmation before republishing/replying. Do not roll back to an incompatible reader after writing Sales data.

Cleanup removes pending inquiries after seven days, inactive verified/reconfirmation-needed conversations after twelve months, abuse fingerprints after 24 hours, suppression after 90 days and expired auxiliary receipts on their documented schedules. Closure keeps the existing recovery/manual-purge process; do not shorten it through this feature. Raw capability paths, bodies, email addresses and credentials must not enter logs or public receipts. Templates disable invocation URL logs and traces; preserve that setting in the live-derived configuration.

## Bounded operation limits

Listing and inbox pages: 100. Exact publication review: 100 items, 15-minute expiry. Fixed bulk selection: 500, split larger work explicitly. Mail lease: 10 items, 60 seconds; final one-use claim required. Workspace send cap: min(configured daily limit, 30). Pilot workspace inquiry cap: 100/day; IP/listing intake: 5/hour; bounded recovery: 3/hour and 5/day per lead, plus recipient cap. Limits are controls, not capacity or performance certification.

## Operator-managed subdomain pilot

For an explicitly approved hostname in the operator's own Cloudflare zone, Workers Custom Domains supplies DNS and certificates without requiring Cloudflare for SaaS activation. This is a distinct qualified path; it does not certify customer apex hosting or SaaS entitlements. Snapshot existing DNS/routes, verify the hostname is unused, preserve the root application/mail records, then attach only the named hosts to `domains-sales-lander`.

The operator observes its exact Workers Custom Domain resource and successful HTTPS edge response, records the observation receipt, and deploys `DOMBOT_SALES_DNS_CONTROL` only to the controlled workspace. Each strict entry binds workspace, canonical domain, SHA-256 proof reference, observation time and expiry (maximum 24 hours). Imported inventory alone still grants no control. The editor labels this source as operator-verified DNS rather than a registrar registration. This metadata is never accepted from a seller API request or portable backup.

`SALES_MANAGED_HOSTS` records the operator-observed Workers Custom Domain ID, exact workspace/hostname/domain/service and the same bounded lease. The controller still requires the listing's current publication, an allowlisted host, exact HTTPS served revision and binding epoch. Ordinary customer/SaaS claims continue to require per-host TXT proof; the managed path uses the separately scoped operator platform-control observation. Its ordinary Cloudflare for SaaS provider remains separate. Registry routing expires at the attestation deadline. Pause/unpublish and detach before removing a managed observation; removing configuration alone is not the revocation workflow. Keep other tenants' Sales flags off.
