# Home layout, filter removal and setup read completion

Date: 5 November 2026. Scope: the existing Domains UI and immutable provisioning artifact reads. Release status is recorded separately after production verification.

## Reproduced defects and repair

The owner's home screenshot showed a detached “Inspect public presence” button, excess vertical space and a short table. The engine `.2` and `.3` renderer HTML, JavaScript and CSS were byte-identical: the dependency-only `.3` release did not introduce new UI assets, but its verification did not catch this existing layout problem. The inspector inherited the full editor's width, margins and bottom padding while sitting outside the filter toolbar. In actual Chrome at 390 × 844, the visible Pricing X was covered by that inspector button; tapping it opened the inspector instead of clearing the filter. Desktop clear tests alone had missed this failure.

The collapsed inspector now uses the existing outline button inside the filter toolbar. Its expanded content retains the existing editor styles. Managed pages also honor short-window spacing at the app's existing 850-pixel height breakpoint. At the screenshot's logical 1512 × 762 viewport, the synthetic fixture table grew from 298 to 407 pixels. The palette, type, wordmark and navigation are preserved.

`home-ui-qualification.mjs` uses official Chrome with a fresh temporary profile and blocks external requests. It accepts only the disposable loopback fixture after checking its synthetic identity. The exact pinned `.4` engine passed eight mouse/touch clear checks: empty Registrar and Folder chips, an active Registrar filter (30 matching rows), and Pricing with zero matching rows, at both desktop and mobile sizes. Each visible X was independently hit-tested; one interaction removed it and restored 50 visible rows of the 60-row fixture without opening the inspector. Inspector open/close also passed at both sizes. Playwright lives in a temporary tools directory, not the project lock or shipped engine.

The provisioning investigation found another concrete indefinite wait: `ASSETS.fetch()` headers and subsequent body consumption had no deadline. Fault injection stalled the module read after a database was created, matching the database-only stranded stage observed in the earlier incident. Both new regressions failed before the change because setup remained pending past 45 seconds.

The shared artifact reader now imposes a **45-second deadline on each immutable artifact read**, aborts its request and cancels its body reader. A late binding response is discarded and has no continuation into provisioning writes. Streaming UTF-8 decoding preserves byte boundaries, and the existing approximate 10 MB post-buffer check becomes an exact **10,000,000-byte maximum enforced during reading**. Both normal provisioning and explicit recovery use it. The bounded private diagnostic/QA receipt classifies this as `artifact_timeout`.

No whole provisioning operation, provider mutation, bootstrap transaction, dispatch write or serialized queue is raced against a new timer. Unknown create/upload results still hold for reconciliation. Retries retain original identities, database and keys. Native Worker → service RPC → setup Durable Object fault tests verify that stalled module headers/body return failure, allow trusted QA cleanup, erase private setup keys/alarm, and cannot upload or recreate resources after a late response. Tests additionally preserve streamed Unicode and cancel oversized artifacts. The exact historical RPC cause remains unproven; the demonstrated unbounded artifact-read failure path is repaired.

## Dependencies and validation

The directly pinned Miniflare alpha's Undici resolution moves from 7.29.1 to 7.30.1 through a narrow override. Its existing supported major and Node requirement remain unchanged; no forced Electron/parser major upgrades were used. The final production audit has zero advisories. The complete development audit has 27 moderate, zero high and zero critical advisories; remaining minimatch-dependent toolchain upgrades require a separately tested parent-toolchain change.

Renderer and lock changes are packaged as pinned engine `2.0.0-hosted.4`, preserving the upstream 2.0.0 revision and archive/source integrity checks. Local typecheck, lint and engine verification pass, with 257 test files / 2,716 passing tests and the existing single manual skip; four security and four relay checks pass. All six Worker dry builds and web/demo/site builds pass. An initial full run hit loopback `EADDRNOTAVAIL` failures in three existing suites while multiple local runtimes/builds were active; all 45 tests in those suites passed in isolation and the subsequent complete four-worker run passed unchanged. Required CI and release receipts must be green before this candidate is described as deployed. Local synthetic tests do not establish physical/production-RP passkey, external inquiry delivery or mainland mailbox acceptance. Prior completed virtual-authenticator checks remain valid and need not be repeated for these unrelated changes.
