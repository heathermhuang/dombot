# Public offer lifecycle and evidence

The additive tenant migration `0009_sales_lifecycle.sql` retains encrypted approved source bindings separately from editable drafts and stores aggregate hosted request/event counters. Apply it before the engine writer. Older whole-money/public records remain readable. New backup extension v3 in bundle v12 preserves counters and explicit core-sale references; v1/v2 sales backups and older bundles remain readable. Restore keeps pages paused, expires operational conversation grants, and does not restore approved public-source authority, routing grants or active publications.

A reviewed market price has a bounded field observation lease, shortened by a known discount expiry. Read-time expiry removes the numerical price/minimum and leaves an approved neutral provider handoff. Changed terms or failed/partial observations mark the approved source stale without rewriting its saved public snapshot. A known inactive/on-hold channel, pending sale, confirmed sale or lost control suppresses conflicting actions. Profile/collection links and shops require current actionable terms. Editing a private draft cannot replace the source binding of the current publication. Recovery, cancellation and reacquisition never reactivate a suppressed offer; current control and explicit publication review remain required.

Seller payment/transfer reports and accepted offers hold the page in `sale-pending`. A completion report suppresses the page but does not create a completed core sale or revenue. Core Sales owns the transaction record and its price, fees, installment and payout evidence. Owners can link a provider transaction, a seller-recorded sale or explicitly match a completed provider transaction to the same exact seller amount/currency. Matching preserves seller facts and does not create a second event. Core sync holds unlinked seller records in the current holding cycle for explicit matching instead of guessing from a nearby date or filling in an unknown price. Cancelled provider imports retain upstream event-reversal behavior. Unavailable evidence is kept as a review task and does not block unrelated account reads.

Hosted measurements are `page-rendered` and `provider-opened` request counts, `inquiry-verified` events and `sale-evidence-linked` events. The latter two deduplicate by existing opaque event receipts. There are no visitor IDs, tracking cookies, additional analytics vendors, unique-visitor estimates or completed-sale attribution. Bots and repeated requests can contribute to request counts. Provider traffic/leads remain separate core source measurements. The owner page reports unavailable measurement storage explicitly rather than synthesizing zero.
