# Connection status and identity return

The connection screen now uses readable stages and separates a published
inquiry page from a custom domain that has passed DNS and public HTTPS checks.
Verified DNS changes and restoration are projected from the existing encrypted
job history. A submitted but unverified operation is not counted as verified;
these read-only numbers do not change execution, fencing or recovery.

Root/www checks and the before/after web routing are visible together. Full
record and public-content details remain available. Expired reviews cannot be
confirmed and offer removal of their unused preview. Recent connections use
singular domain counts, readable states and timestamps.

Identity prompts explain that the account is already signed in and that the
five-minute check protects the DNS change. The saved connection view reopens
after confirmation, including when the email opens another tab in the same
browser. Only a validated view identifier and cursor are retained. No approval,
DNS action, digest or external destination is stored or replayed. Passkey,
email-code, password, origin and fresh-authentication requirements are unchanged.

The portfolio badge says Published for the inquiry page. It does not infer that
the domain itself is connected. Existing Archivo, forest/neutral colors, theme
variables and touch targets are retained.
