# Renewal-pricing cooldown and sales challenge sizing

The live UI review found background pricing repeatedly receiving 429 responses
and a loaded sales-inquiry security widget escaping its narrow tablet form.

The gateway retains its aggregate limit of 20 provider refresh requests per
ten-minute bucket. Background pricing can use at most 15 of those slots, leaving
five available for owner refresh actions. Both limits use the decoded API method
identity. A rejected request includes Retry-After for the bucket reset. The web
client retains that cooldown across revision polling, cache hydration and
inventory reads, shows a local retry time, and automatically resumes the persisted
job even in a hidden tab. Older gateways without a valid retry header receive a
ten-minute fallback. Provider-specific pacing and write/authentication guards are
unchanged.

Sales inquiry challenges choose compact size when their actual container is
narrower than 300px, the minimum width of Cloudflare's flexible widget. A
ResizeObserver recreates a widget only when it crosses that size boundary. It
clears submission readiness until the new challenge succeeds; it does not change
visitor fields, inquiry authority, server verification or the page layout.

Regression coverage includes shared/independent workspace quotas, encoded API
method names, owner refresh capacity, numeric/date/missing retry headers, repeated
revision polls, hidden-tab recovery, and challenge sizing/resizing/readiness.
The existing passkey session-preservation assertion compares session records
rather than nondeterministic D1 query duration metadata.

The paired engine and UI artifact is version 1.5.2-hosted.7. No schema migration,
credential change, publication change or alternate founder-site deployment is
required. Release completion requires exact-head CI, preserved provider bindings,
enabled-runtime provenance checks, and fresh browser verification of both defects.
