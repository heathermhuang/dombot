# Unlisted-domain inquiries

The staging form at `/request-domain` sends email-confirmed inquiries to the designated reviewer's existing Sales Inbox. The case stores the requested name in its encrypted payload and has no sale-draft reference. The form accepts a requested name without consulting registrar inventory, publication status, or ownership. Only the configured review workspace receives the case.

Enable this route only on an isolated QA Worker with public registration disabled. Set `OFF_MARKET_STAGING_REVIEWER` to the controlled reviewer's account ID and `OFF_MARKET_STAGING_BUYER_EMAIL` to the controlled buyer inbox. Configure and verify the existing Sales mail delivery and Turnstile bindings. The route requires a verified seller recipient and accepts submissions only from the configured buyer address. The buyer confirms their email, opens the same private conversation after each reply, and can renew a link through the existing recovery flow.

Tenant migration `0013_unlisted_domain_inquiries.sql` preserves listed cases, replies, tokens and notification delivery state. Snapshot the isolated database before applying it, compare case and child counts afterward, and deploy engine `2.2.2-hosted.13` and its compatible gateway before enabling the route. Backup format 19 and Sales version 7 preserve unlisted cases and their messages. Restore expires buyer verification and omits tokens and delivery intents. Keep a compatible engine and gateway once a new case is saved. Disable the reviewer setting to close intake while retaining the Inbox and conversation reader.

In staging, check the exact case count after replay, email confirmation and reply, renewal, cross-host and cross-workspace denial, suppression, and backup restore. Delete disposable cases and verify the case, message, token and outbox counts. A named production reviewer must accept the queue before public activation.
