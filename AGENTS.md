## Hosted authentication

- Future production import tests must use `scripts/production-import-qualification.mjs` and its trusted QA-run leases, with cleanup in `finally`/`always`. Browser tests use `--mode prepare` and `--mode cleanup`; the provisioner expiry reaper covers killed/abandoned runners. Never seed ad hoc QA users or select cleanup targets by name prefix. Unexpected identities/data are holds, and failed cleanup blocks further tests. See `docs/production-import-qa.md`.

- On-demand provisioning is implemented behind `ON_DEMAND_ENABLED`; it is not enabled by source changes alone. Signup creates only control metadata. Allocate on the first credential submission or a valid import submission (opening Import and local preview allocate nothing), qualify runtime identity/idle state before admission, and retain stable setup identities/keys across retries. Existing customers are never migrated or reclaimed by this path. See `docs/on-demand-provisioning.md`.
- Conference reserve retirement is a separate, exact-manifest operation. Unowned rows and initialization records do not by themselves prove deletion eligibility. The planner is read-only, checkpoints completed reads and stops on actual provider rate limits; preserve unknown/data-bearing resources.

- Run `npm ci --prefix hosted --ignore-scripts` and `node hosted/build-auth.mjs` after the normal root dependency install, before hosted typechecks/tests/bundles. Auth dependencies belong to `hosted/package.json` so they do not change the pinned tenant engine.
- The default account journey uses ten-minute single-use email links/codes and optional passkeys. Preserve explicit legal acceptance, qualified capacity, immutable identities, existing password access, single-use challenge transactions and five-minute fresh authentication for sensitive actions. New registrar connections use the active session without a second identity check; saved credentials and other sensitive actions retain fresh authentication. Once a passkey exists, email/password sign-in must not bypass the passkey check for those sensitive actions. See `docs/passwordless-auth.md`.
- QQ/163/126 inbox delivery and mainland-China network access require actual controlled receipts; never infer them from Google mailbox delivery or removal of Google login dependencies.

## Changelog upkeep

- Release and source events are added by `.github/workflows/changelog-sync.yml`, on main pushes, release publication/editing, the release workflow's reusable call, and quarter-hour catch-up checks. The nightly reconciliation walks every release/merged-change page, including older or backdated publications. Unchanged source fingerprints produce no Git commit; no model is involved.
- Hand-written notes are optional enrichment in `changelog-notes/<id>.json`. Do not make future app changes depend on someone remembering a changelog entry. Published GitHub releases, merged PRs, primary source commits, verified release receipts and public gateway-source observations have distinct labels. A merge/publication does not prove tenant deployment; an observation date is not an inferred deployment time.
- `site/public/changelog-index.json` and `site/public/changelog-archive/*.json` are the permanent archive. Pages are bounded, but total history has no entry-count cutoff. Never delete/move an archived ID, remove its historical source links or discard an old page. CI and the publisher validate the entire archive before publication. Fail incomplete API pagination rather than publishing a partial history. Use normal non-force pushes; a concurrent main change is retried by the next sync, never overwritten.
- `site/public/changelog-legacy.json` preserves the original root-fragment permalinks and offline snapshot. New headings use stable archive-page addresses. The public page provides older/newer pages, year navigation and a beginning link. Paginating history must never make old records unreachable.
- Keep the core origin (30 August 2026 UTC), hosted origin (9 September), all historical releases and `docs/changelog-history-inventory-20261106.json` coverage. Preserve bounded origin reads, public-only source data, escaped output and explicit stale/unavailable states. No customer/session authority is forwarded to GitHub. See `docs/changelog.md`.
